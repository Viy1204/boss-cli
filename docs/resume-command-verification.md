# 简历命令核对记录

核对日期：2026-10-28。参考用户提供的 `liepin-resume-commands.md`，检查 Boss CLI 的列表、会话、在线简历与附件请求链路。

## 能力对照

| 场景 | Boss 命令 | 实际行为 |
| --- | --- | --- |
| 读取已建立的会话 | `list` → `chat <姓名> --strict` 或 `chat [姓名] --index N` | 输出候选人摘要及当前已加载消息，未自动加载全部历史 |
| 读取聊天中的在线简历 | `action resume` | 直接打开在线简历并保存 PNG；不要求先索取附件，也不要求对方已回复 |
| 读取推荐候选人的在线简历 | `recommend` → `preview [姓名] --index N` | 直接打开目标简历，无须先打招呼；姓名不唯一时必须用序号 |
| 读取搜索候选人的在线简历 | `search <关键词>` → `preview [姓名] --index N` | 复用搜索快照与候选人身份校验，无须先打招呼 |
| 获取 OCR 文字 | 显式开启 `BOSS_RESUME_OCR=1`，再运行上述简历命令 | 需要百度 OCR 配置；输出截图识别文本，保留截图路径，不是结构化简历 JSON |
| 索要附件 | `action request-attachment-resume` | 会向候选人发送请求，独立于在线简历读取 |
| 同意接收附件请求 | `action agree-resume` | 处理对方请求卡片，不下载文件 |
| 按简历 ID 读取、附件下载、结构化简历 JSON | 无对应命令 | 当前未实现；不能把其他平台的 ID 或命令参数直接套用 |

在线简历截图保留页面当前展开状态，不自动展开“查看全部”；OCR 不能据此保证全文。聊天中的“附件简历消息：未发现”仅表示当前已加载消息里没有附件标识，不表示在线简历不可读。

## 本轮确认并修复的问题

| 问题 | 修复前证据 | 修复方式 |
| --- | --- | --- |
| 后台窗口导致列表/会话误报超时 | 真实 `list` 报 `Waiting failed: 15000ms exceeded`；`chat` 的选中姓名和详情姓名均匹配仍报错。同一隐藏页的条件延迟变真时，rAF 等待超时，100ms 定时轮询通过 | 列表、会话详情与消息就绪使用 100ms 定时轮询 |
| 未读序号可能定位到已读人 | 离线行为测试中，`list --unread` 从全部列表过滤，旧 `chat --index --unread` 却使用平台未读页签和另一套节点编号，实际点击已读候选人 | 统一从全部列表的非空姓名卡片编号，再按未读角标过滤；失配和越界在点击前拒绝 |
| 仅有简历卡片的会话被误判未加载 | 旧就绪条件只认文字或系统标题，后续读取器却已支持附件卡片 | 就绪条件接受读取器支持的卡片内容，空列表/空消息壳仍拒绝 |
| 推荐候选人重复输出及引导卡误算 | 真实 DOM 中 15 个 `.card-item` 各包着一个 `.candidate-card-wrap`，联合选择器重复计数；另一轮还混有无简历入口的“热搜牛人推荐”引导卡 | 统一以 `.candidate-card-wrap:not(.anonymous-geek-guide-card)` 为候选根，普通候选人仍须有平台标识 |
| 推荐摘要漏读工作与教育 | 旧 `.experience-wrap` 在真实普通卡片上均不存在 | 按 `.work-exps` / `.edu-exps` 时间线读取日期、公司、岗位、院校、专业和学历，并纳入快照 |
| 搜索预览因窗口布局变化被拒绝 | 同一批 15 张搜索卡，13 张标签在后台为零项，窗口显示后变为若干项；DOM 和身份未变 | 使用 `.info-tags-measure` 的完整标签集合，排除显示截断影响；真实标签变化仍拒绝 |
| 同名预览静默选择第一人 | 两张同名、不同平台标识的卡片，旧搜索与推荐预览都只点第一个；CLI 不支持 `--index` | 支持序号；姓名须唯一匹配；校验列表快照、顺序、资料与身份后点击目标 |
| 输出混淆附件与在线简历 | “简历获取状态：未获取”只依据附件卡片；“完整聊天消息”未实际加载全部历史 | 明确标为附件消息状态、当前已加载聊天消息，并提示可直接读取在线简历 |
| 截图告警与失败原因丢失 | 模拟截图边界告警被忽略；OCR 开启后截图路径消失；截图失败统一变成“未找到入口” | 保留截图路径、告警、具体错误及 OCR 原始错误 |
| 提交发送被描述为发送成功 | 无任何送达确认的模拟会话仍返回“已发送消息”；后续索要附件失败不交代文本已提交 | 返回“已提交发送（未确认送达）”；后续失败保留部分执行事实，提示先核对记录再重试 |

## 验证边界

真实平台核对只执行列表、已有会话读取、搜索、推荐和在线简历截图。发送、索要附件、同意附件、打招呼及不合适操作没有对真实候选人执行，相关失败与返回语义用隔离测试验证。

本轮使用真实候选人验证读取能力，不对候选人作评级或更新招聘台账。回归 fixture 使用虚构候选人与标识。
